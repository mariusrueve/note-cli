# Shell completion

Scripts are generated by Cobra, without config or dependencies. Generation does
not edit startup files. See [verification](verification.md) for executed smoke
checks and remaining native checks.

Bash (load directly, or save to your bash-completion directory):

```sh
source <(note completion bash)
```

Zsh (add to `.zshrc`, with completion initialized):

```sh
autoload -Uz compinit
compinit
source <(note completion zsh)
```

Fish:

```fish
mkdir -p ~/.config/fish/completions
note completion fish > ~/.config/fish/completions/note.fish
```

Completion resolves paths relative to your knowledge root, regardless of the
current directory. Type `note new chemin` then Tab for `cheminformatics/`; nested
prefixes work too. Empty and ignored ordinary directories are included. Hidden
directories, symlinks, `.git`, and nested repositories are excluded. Note file
suggestions honor discovery's ignore rules. Directories end in `/` and use the
no-space directive; mixed suggestions may require adding a space after a file.

Root completion also offers registered commands. `open` and `new` suggest note
paths, `new --template` suggests effective template identifiers, and `--config`
uses ordinary local file completion. Missing ripgrep omits file suggestions but
still offers directories/templates. Invalid or missing config quietly omits
knowledge paths; embedded template suggestions remain available. Completion is
read-only and never opens an editor, starts a picker, or contacts a remote.

Cobra's completion protocol uses lines and tabs, so names containing control
characters are omitted from completion candidates. Their identities remain
available through JSON, the picker, and literal `open` arguments.

If it fails, check that `note` is on PATH, reload the shell script after updating,
and run `note doctor`. Test the underlying protocol with
`note __complete new chemin`; a final `:6` means no file completion and no space.
